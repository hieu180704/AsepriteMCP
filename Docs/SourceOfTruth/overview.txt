# 1. Mục Tiêu & Định Nghĩa Cốt Lõi

- **Tên dự án:** AsepriteMCP
- **Loại:** Dự án **ứng dụng** — dùng MCP để AI làm việc được qua Aseprite. [GT]

- **ĐỊNH NGHĨA QUAN TRỌNG NHẤT — KHÔNG tự xây MCP server:** [GT — người dùng xác nhận 2026-08-18]
  AsepriteMCP là dự án **sử dụng** một MCP server có sẵn để AI thao tác với Aseprite, KHÔNG phải
  dự án viết ra một MCP server mới. Bản `/init` đầu tiên đã diễn giải sai điểm này và đã được sửa.
  Mọi đề xuất kiểu "ta nên tự viết server bằng ngôn ngữ X" đều đi ngược định nghĩa dự án — đừng đề
  xuất lại trừ khi người dùng chủ động đổi ý.

- **Mục đích tồn tại:** Cho phép AI thao tác trực tiếp lên file pixel art của Aseprite thay vì chỉ
  mô tả bằng lời — biến Aseprite thành một công cụ mà AI gọi được. [GT]

- **Ràng buộc — Model-agnostic:** Thiết lập KHÔNG dành riêng cho Claude. Bất kỳ AI model hay MCP
  client nào cũng phải dùng được: Claude Code, Claude Desktop, Cursor, Cline, Continue,
  ChatGPT/OpenAI, Gemini và các client MCP tương lai. [GT]
  → Hệ quả: server được chọn phải giao tiếp bằng MCP tiêu chuẩn; cấu hình giữ ở dạng `.mcp.json`
    phổ thông để client nào cũng copy sang được; không dùng tính năng riêng của một client. [INF]

- **Ba mục tiêu cốt lõi (đầu ra kỳ vọng):** [GT]
  1. **AI tự tạo pixel art** — vẽ, sửa, quản lý layer/frame, animate sprite qua tool calls.
  2. **Tự động hoá export asset** — batch export sprite sheet, atlas, JSON metadata theo
     convention cố định.
  3. **Dùng nội bộ cho game Unity** — phục vụ workflow làm game Unity của chính người dùng.

- **Không nhắm public/open-source.** Người dùng không chọn mục tiêu "Open-source / chia sẻ". [GT]

# 2. Phạm Vi (In-scope / Out-of-scope)

## 2.1. In-scope
- Chọn, cài đặt, cấu hình và vận hành MCP server cho Aseprite. [GT]
- Thông qua server đó: tạo/chỉnh sửa file `.aseprite`, thao tác layer/frame/cel/palette/tag,
  vẽ pixel và hình cơ bản, fill, chọn vùng, áp palette. [GT]
- Export: sprite sheet, atlas, PNG rời, JSON metadata mô tả frame/tag. [GT]
- Batch processing nhiều file theo convention. [GT]
- Viết lớp phụ trợ **bên ngoài server** nếu cần (script export, quy ước đặt tên, glue code đưa
  asset vào Unity). Đây không phải "tự xây server" nên không mâu thuẫn định nghĩa ở mục 1. [INF]

## 2.2. Out-of-scope
- **Tự viết một MCP server mới cho Aseprite.** Đã loại dứt khoát. [GT]
- Fork và tự maintain server upstream như một sản phẩm riêng. [INF]
- Phát hành công khai bất cứ thứ gì lên npm/PyPI/GitHub cho cộng đồng. [GT]
- Tự sinh art bằng model diffusion/AI image generation — dự án điều khiển Aseprite, không thay thế
  nó bằng generative image model. [INF]

# 4. Kiến Trúc Thực Tế

Đây là kiến trúc đang chạy thật trên máy, không phải đề xuất. [GT — đã kiểm chứng 2026-08-18]

```text
[AI Client bất kỳ]                 (Claude Code / Cursor / ChatGPT / Cline ...)
        │  MCP protocol qua stdio
        ▼
[diivi/aseprite-mcp]               vendor/aseprite-mcp — Python 3.13 chạy bằng uv
        │  116 tools
        │  sinh file .lua tạm → gọi aseprite --batch --script <file> → xoá file tạm
        ▼
[Aseprite 1.3.17.2]                đường dẫn khai báo qua ASEPRITE_PATH
        │
        ▼
[File .aseprite / PNG / JSON]  ──►  [Unity project]   ← khoảng trống, xem mục 5.1
```

Phần dự án có thể cần tự làm nằm ở mũi tên cuối cùng: đưa asset từ đầu ra của server vào Unity
theo đúng convention. Upstream không giải quyết thay được vì convention là thứ riêng của mỗi dự án.

## 5.3. Hooks không chạy trên Claude Code — ĐÃ XỬ LÝ 2026-08-18
[GT — kiểm chứng 2026-08-18 bằng schema chính thức tại https://code.claude.com/docs/en/hooks]
Năm lỗi độc lập, mỗi lỗi đủ để vô hiệu hoá hooks (hoặc một hook). Cả năm đã sửa xong:
  1. Cấu trúc sai: `.claude/settings.json` dùng `{matcher, command}`, schema đúng là
     `{matcher, hooks:[{type:"command", command}]}` — thiếu mảng lồng bên trong. → ĐÃ SỬA.
  2. Matcher sai: `"tool == 'Write' || tool == 'Edit'"` chứa ký tự đặc biệt nên bị Claude Code
     hiểu là regex và không khớp tool nào. → ĐÃ SỬA thành `"Write|Edit|MultiEdit|NotebookEdit"`.
  3. Input sai: `safety-guard.js` và `read-guard.js` đọc `process.argv[2]`, nhưng Claude Code
     gửi dữ liệu qua **stdin dạng JSON**. → ĐÃ SỬA, xem cách làm bên dưới.
  4. Exit code sai (phát hiện thêm khi thực hiện): guard trả `process.exit(1)`, mà với Claude Code
     exit 1 là *non-blocking error* — in cảnh báo rồi vẫn cho tool chạy tiếp. Muốn chặn thật phải
     là **exit 2** (chặn tool + đẩy stderr về cho model đọc). → ĐÃ SỬA.
Hệ quả trước khi sửa: `safety-guard.js` luôn nhận chuỗi rỗng nên không pattern nào khớp — guard bảo
vệ `.env` là hình nộm, luôn trả SAFE. Kể cả khớp cũng không chặn được vì lỗi 4.

**Cách sửa lỗi 3 — quyết định thiết kế [GT, người dùng chốt 2026-08-18]:** không sửa argv → stdin,
vì như vậy chỉ đổi giả định sai này lấy giả định sai khác; dự án phải chạy trên *mọi* AI client
(hiện Claude, sau có thể Antigravity, Cursor...) và mọi thiết bị. Giải pháp: module dùng chung
`.agents/hooks/hook-io.js` tự dò input — ưu tiên stdin JSON, không có thì rơi về argv; parse được
JSON thì chỉ duyệt nhánh tham số tool (`tool_input`/`arguments`/`params`/`input`), gom giá trị dưới
key khớp `/path|file|filename|target|uri|url/i`. **Chỉ soi đường dẫn, không soi nội dung file** —
nếu match cả payload thì một lệnh ghi tài liệu có nhắc chữ `.env` sẽ bị chặn oan.
Kiểm chứng: 15 ca test qua CLI (stdin JSON an toàn/nhạy cảm, argv an toàn/nhạy cảm, payload phẳng
kiểu client lạ, input rỗng, read-guard png/pdf/text, closeout-trigger lọc đúng `git commit` và im
với lệnh khác) — đúng exit code cả 15. Ca đáng giá nhất: payload có `content` chứa chữ `.env` và
`secrets` nhưng `file_path` sạch → vẫn SAFE, log ghi "kiểm 1 đường dẫn" chứng minh `transcript_path`
trong metadata phiên cũng bị loại đúng thiết kế.
`.agents/hooks.json` giữ nguyên: matcher `tool == '...'` vẫn hợp lệ phía Antigravity, script giờ ăn
được cả hai giao thức.

**Wiring đã kiểm chứng thực tế ngay trong phiên 2026-08-18 [GT]:**
  - Lệnh `Write` lên một file `.env` → **bị chặn**, Claude Code trả về
    `PreToolUse:Write hook error: [SAFETY VIOLATION] ...` và file không được tạo. Đây là bằng chứng
    trực tiếp rằng cả schema, matcher, cách đọc input lẫn `exit(2)` đều đúng.
  - Lệnh `git commit` → `closeout-trigger.js` bắn `[LIVING DOCS REMINDER]` vào ngữ cảnh model qua
    `additionalContext`, và im lặng với các lệnh Bash khác.
  - `read-guard.js` dùng chung đường ống đó nhưng thoát 0 nên không có tín hiệu nhìn thấy được
    trong phiên; chỉ kiểm chứng được ở mức CLI.
Đính chính một nhận định sai đã nêu lúc đang làm: Claude Code **có** nạp lại `.claude/settings.json`
trong phiên, không phải chỉ chụp lúc khởi động như phỏng đoán ban đầu.
**Lỗi 5 — `closeout-trigger.js` là file chết phía Claude (phát hiện và sửa cùng đợt).** Script được
sync sang `.claude/hooks/` nhưng không đăng ký trong `settings.json`. Đã nối dây với matcher
`"Bash"`. Vướng mắc kèm theo: matcher của Claude Code chỉ khớp **tên tool**, không soi được nội
dung lệnh như matcher Antigravity (`command.includes('git commit')`), nên bộ lọc `git commit` phải
chuyển vào trong script. Quy tắc chọn: input rỗng thì cứ nhắc (tin bộ lọc phía client cũ), chỉ im
lặng khi đọc được input và biết chắc không phải `git commit`.
Script cũng đổi cách in: client nói JSON thì trả `hookSpecificOutput.additionalContext` để nội dung
nhắc vào được ngữ cảnh model — stdout text thuần với exit 0 chỉ hiện ở transcript, model không đọc
được. Client cũ vẫn nhận text thuần như trước.

## 7.4. Bộ recipes thao tác Aseprite (2026-08-18) [GT]
Nguồn tại `.agents/recipes/`, đã sync sang `.claude/recipes/`:
- `aseprite-00-playbook.md` — **đọc trước tiên.** Giới hạn đã biết của AI, 8 rule cứng, giao thức
  kiểm chứng 2 tầng (text cho mọi client / ảnh cho client đọc được ảnh), bảng tra tool.
- `aseprite-static-sprite.md` — vẽ sprite tĩnh, quy trình 7 bước.
- `aseprite-animation.md` — animation nhiều frame, trọng tâm là propagate + tween thay vì vẽ lại.
- `aseprite-edit-existing.md` — recolor/resize/batch, nhóm việc AI làm tốt nhất.

Ba rule cứng quan trọng nhất rút ra: (1) luôn dùng biến thể tool `*_at` để tránh active-cel drift;
(2) chốt palette và ramp màu trước khi vẽ; (3) cấm báo hoàn thành khi chưa đọc lại kết quả bằng
