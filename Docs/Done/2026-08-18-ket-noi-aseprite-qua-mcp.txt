# 3. Chi Tiết Thay Đổi

## 3.1. Tệp đã tạo
- `vendor/aseprite-mcp/` — clone `diivi/aseprite-mcp` (depth 1).
- `vendor/aseprite-mcp/.env` — khai báo `ASEPRITE_PATH`.
- `mcp-client-config.example.json` (gốc dự án) — cấu hình MCP mẫu cho client khác. Ban đầu đặt tên
  `.mcp.json` nhưng đã đổi tên: Claude Code tự nạp `.mcp.json` thành server scope `project`, trùng
  với entry scope `local` và sinh cảnh báo "defined in multiple scopes".
- Đăng ký Claude Code ở scope `local` bằng `claude mcp add` — ghi vào `C:\Users\Admin\.claude.json`.
  Cách này bỏ được bước approve thủ công mà `.mcp.json` project-scoped bắt buộc phải qua.

## 3.2. Tệp tài liệu đã cập nhật
- `Docs/SourceOfTruth/overview.txt`:
  - Kết luận đã kiểm chứng về cơ chế điều khiển Aseprite (CLI + Lua).
  - Nêu câu hỏi hướng đi dự án — tự xây hay dùng server có sẵn.
  - Bổ sung rủi ro về bản cài Aseprite hiện tại.
  - Cập nhật trạng thái + chi tiết hạ tầng MCP đã cài.

  *Lưu ý:* file này sau đó được cấu trúc lại trong cùng ngày khi người dùng đính chính định nghĩa
  dự án, nên số hiệu mục ở trên không còn khớp. Tra theo tiêu đề mục thay vì theo số.

## 3.3. Kiến thức kỹ thuật thu được
- Cơ chế điều khiển Aseprite của server: sinh file `.lua` tạm → gọi
  `aseprite --batch --script <file>` → xoá file tạm. Xem `aseprite_mcp/core/commands.py`.
- Chất lượng code upstream tốt: có escape chuỗi Lua và chặn path traversal
  (`commands.py` — hàm `lua_escape` và `reject_traversal`).
- Số tool thực tế là **116**, không phải 104 như README ghi.

# 4. Kết Quả Kiểm Chứng

## 4.1. Smoke test end-to-end (ĐẠT)
Tạo canvas 32x32 → thêm layer "art" → vẽ 3 pixel → export PNG. Sau đó **đọc lại file PNG bằng
Pillow để verify độc lập**, không chỉ tin vào thông báo thành công của tool:
- `pixel(5,5) = (255,0,0,255)` — đỏ, đúng.
- `pixel(6,5) = (0,255,0,255)` — lục, đúng.
- `pixel(7,5) = (0,0,255,255)` — lam, đúng.
- `pixel(0,0) = (0,0,0,0)` — nền trong suốt, đúng.

## 4.2. MCP handshake qua stdio (ĐẠT)
Dò bằng JSON-RPC thô: `initialize` trả về `serverInfo={name:"aseprite", version:"1.6.0"}`,
protocol `2024-11-05`; `tools/list` trả về **116 tools**.

## 4.3. Ghi chú về một lần test thất bại
Lần thử đầu dùng Python MCP client SDK bị treo quá 180s. **Đây là lỗi của script test, không phải
lỗi server** — đã chứng minh bằng cách dò JSON-RPC thô thành công ngay sau đó. Ghi lại để phiên sau
không chẩn đoán nhầm là server hỏng.

## 4.4. Trạng thái đăng ký
`claude mcp list` báo server `aseprite` ở trạng thái **"Pending approval"**. Đây là hành vi đúng của
Claude Code với server project-scoped, không phải lỗi. Người dùng phải tự chạy `claude` và duyệt.

# 5. Vấn Đề Phát Hiện — Cần Người Dùng Quyết

## 5.1. Bản Aseprite đang dùng là bản bẻ khoá
Đường dẫn: `C:\Users\Admin\Downloads\Aseprite.v1.3.17.2_LinkNeverDie.Com\Aseprite.exe`, đi kèm
Steam emulator. Hai hệ quả: (1) nằm trong `Downloads/` nên đường dẫn chắc chắn sẽ gãy khi thư mục
bị dọn; (2) rủi ro pháp lý khi dùng sản xuất asset cho game thương mại.
Khuyến nghị: mua bản quyền (~$19.99) và cài vào đường dẫn cố định. Chi tiết ở mục 6 của
`overview.txt`.

## 5.2. Mâu thuẫn định hướng dự án — ĐÃ GIẢI QUYẾT cùng ngày
Dự án được khởi tạo với định nghĩa "tự xây MCP server", nhưng yêu cầu lần này dẫn tới việc cài một
server có sẵn đã bao phủ gần hết mục tiêu.

**Kết luận:** người dùng đính chính ngay trong ngày — định nghĩa "tự xây" là do AI diễn giải sai ở
phiên `/init`. Bản chất dự án là **dùng MCP server có sẵn**, không tự xây. Đã chốt phương án A.
Xem `Docs/Decisions/2026-08-18-dung-mcp-server-co-san.txt`.

## 5.3. Đề xuất nhỏ chưa thực hiện (chờ duyệt, không tự làm)
Nếu sau này `git init` cho dự án, nên thêm `vendor/` và `.env` vào `.gitignore`.
